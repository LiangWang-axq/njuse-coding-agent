# Coding Agent 2 分钟演示视频大纲与操作稿

## 一、视频目标

在 2 分钟以内演示 Coding Agent 完成一个真实的 Python 编程任务：检查订单金额模块、根据项目现状定位并修复问题，并用测试验证结果。同时展示多轮对话模式下的工作区选择能力。

建议成片时长：1 分 50 秒左右；格式：MP4、H.264；文件大小：不超过 200 MB。

本视频必须让观众看到完整闭环：

```text
选择工作区 → 判断测试现状 → 输入自然语言任务 → Agent 读取代码和文档
→ 定位问题 → 修改源代码 → 补充或运行测试 → 验证结果 → 查看工作区状态
```

## 二、录制前准备

以下操作在录制前完成，不必录入视频：

1. 在项目根目录完成一次本地安装：

   ```powershell
   Set-Location "$HOME\Desktop\agent"
   python -m pip install -e . --no-deps
   ```

2. 确认模型配置可用。API key 只放在 `.env` 或系统环境变量中，不要在视频中打开、复制或展示 `.env`。
3. 确认演示目录处于初始状态。当前演示目录预置了一个带两个 bug 的订单模块和 3 个测试；如果换成没有测试的项目，不要提前创建测试，交给 Agent 根据项目说明补充：

   ```text
   demo/tasks/fix_me/orders.py       保留两个故意设置的 bug
   demo/tasks/fix_me/tests/test_orders.py  当前演示保留 3 个测试
   ```

4. 为了证明后续改动确实来自 Agent，先把“带 bug 的演示状态”作为 Git 基线提交。必须在独立的演示分支执行，避免把其他开发改动带入提交：

   ```powershell
   git switch -c demo/agent-diff-baseline
   git add demo/tasks/fix_me/orders.py
   git commit -m "chore: restore demo bug baseline"
   git diff -- demo/tasks/fix_me/orders.py
   ```

   最后一条命令应无输出。若当前分支已经有同名分支，则改用其他本地演示分支名；不要提交 `.env`、会话文件或其他无关改动。录制前还要确认 `git status --short -- demo/tasks/fix_me` 没有输出。

5. 关闭无关窗口，打开一个较大的 PowerShell 窗口，建议字体 18 至 22 号，保证工具调用和测试结果清晰可见。
6. 录制时从项目根目录开始，不要手动设置 `PYTHONPATH`。

### 2.1 正式录制时的完整按键顺序

正式录制时建议始终从项目根目录开始，严格按下面顺序操作：

```text
1. Set-Location "$HOME\Desktop\agent"
2. Get-Location
3. git diff -- demo/tasks/fix_me/orders.py
4. git status --short -- demo/tasks/fix_me
5. Push-Location .\\demo\\tasks\\fix_me
6. Get-ChildItem -File tests
7. python -m unittest discover -s tests -v
8. Pop-Location
9. python -m coding_agent
10. /workspace .\demo\tasks\fix_me
11. /status
12. 输入编程任务并回车
13. 等待 Agent 自主完成工具调用和测试
14. /status
15. /exit
16. git diff -- demo/tasks/fix_me/orders.py
17. git status --short -- demo/tasks/fix_me
```

第 3 至第 8 步用于确认 Git 基线和初始失败状态：第 3 步的 `git diff` 应无输出，第 4 步的状态也应无输出；第 7 步再展示两个测试失败。第 9 步以后进入正式多轮对话。第 12 步回车后不要抢先输入下一条消息，必须等 Agent 返回最终总结并重新出现 `你 >` 提示符；第 15 步退出后，第 16 步的 diff 才能展示 Agent 的实际改动。

如果第 10 步使用绝对路径，路径中包含空格时要把整个路径放在英文双引号中；如果使用相对路径，路径相对于当前显示的工作区解析。录制时优先使用相对路径，画面更短、更清楚。

## 三、推荐录制流程

### 0:00-0:07：标题和项目定位

画面操作：

1. 打开 PowerShell，显示项目根目录：

   ```powershell
   Set-Location "$HOME\Desktop\agent"
   Get-Location
   ```

2. 画面停留 1 秒，让观众看到项目目录。

口播：

> 这是一个不依赖第三方 Agent 框架的 Python 编程智能体。它可以在指定工作区内读取文件、理解项目说明、修改代码、补充或运行测试，并通过多轮对话持续完成任务。

剪辑：

- `cd` 和 `Get-Location` 可以正常速度播放；
- 不要展示项目根目录中的 `.env` 内容。

### 0:07-0:20：确认 Git 基线、检查测试并进入多轮工作区选择

画面操作：

1. 留在项目根目录，先展示修复前的 Git 工作区状态：

   ```powershell
   git diff -- demo/tasks/fix_me/orders.py
   git status --short -- demo/tasks/fix_me
   ```

   两条命令都应无输出。随后进入演示目录，检查测试目录并运行初始测试：

   ```powershell
   Push-Location .\demo\tasks\fix_me
   Get-ChildItem -File tests
   python -m unittest discover -s tests -v
   Pop-Location
   ```

2. 保留测试失败输出，重点让观众看到：

   ```text
   Ran 3 tests
   FAILED (failures=2)
   ```

3. 回到项目根目录后启动 Agent，不需要进入目标目录，也不需要设置环境变量：

   ```powershell
   python -m coding_agent
   ```

4. 启动画面出现后，在 `你 >` 后输入：

   ```text
   /workspace .\demo\tasks\fix_me
   ```

5. 切换成功后继续输入：

   ```text
   /status
   ```

6. 停留在状态输出，确认画面中出现：

   ```text
   工作区: $HOME\Desktop\agent\demo\tasks\fix_me
   ```

口播：

> 在让 Agent 修改之前，我先用 Git 确认演示文件没有未提交变化，后面出现的 diff 才能作为本轮修改的客观证据。接着我检查项目是否有测试。当前演示目录包含三个订单测试，其中两个失败：一个是金额格式化测试，期望结果带有人民币符号，但实际结果没有；另一个是折扣计算测试，期望九十九元打九折后得到八十九点一元，但实际结果是八十九元。这里我只说明失败现象，不直接告诉 Agent 修改哪一行。现在进入多轮对话，通过 `/workspace` 选择演示项目作为工作区，Agent 的文件操作和测试都会绑定到这个目录。

剪辑：

- `Get-ChildItem` 和失败测试不要加速；
- `/status` 的工作区路径至少保留 2 秒；
- 如果路径较长，可以把 PowerShell 窗口横向拉宽，避免换行。

### 0:20-0:30：输入编程任务

画面操作：

在 `你 >` 后输入以下任务，建议提前复制到剪贴板，但录制时只展示粘贴后的完整内容：

```text
请检查当前工作区并修复实现中的问题，不要假设项目已经存在测试。先查看项目结构、README、注释和相关代码：如果已有测试，先运行测试并根据失败输出定位根因；如果没有测试，请根据项目文档、注释和现有接口编写最小回归测试。不得修改、删除或放宽已有测试，不得通过绕过测试来完成任务。修复源代码后运行全部测试，必要时补充边界条件测试，全部完成后总结修改内容和验证结果。
```

按回车后不要继续输入，等待 Agent 开始输出。

口播：

> 这里不直接告诉它修改哪一行，也不假设项目一定有测试。我要求 Agent 先判断测试现状：有测试就根据失败信息定位问题，没有测试就根据文档、注释和接口行为补充回归测试，再修复源代码并验证。

### 0:30-0:58：Agent 发现并分析代码

画面操作：

1. 保留 Agent 的第一段说明文字。
2. 保留 `list_files` 工具卡片，展示它确认了当前工作区的文件结构。
3. 保留 `read_file` 工具卡片，展示它读取了 README、订单源代码和测试文件；如果没有测试，则保留它读取 README、注释或接口定义的画面。

   ```text
   orders.py
   tests/test_orders.py
   ```

4. 如果出现 `search_code`，保留搜索订单函数或金额计算关键字的那一帧。
5. 如果 Agent 先运行测试，保留 `run_tests` 返回失败的卡片和失败摘要；如果项目没有测试，保留 Agent 创建回归测试文件的 `write_file` 工具卡片。

预期看到的工具调用顺序大致为：

```text
list_files → read_file → 判断测试现状 → run_tests 或 write_file → 分析问题
```

实际模型可能调整顺序，不需要为了完全一致而重录；只要能看到读取代码、理解测试和定位问题即可。

口播：

> Agent 先查看工作区结构、项目说明和相关源代码，然后判断测试现状。当前项目已有测试，所以它根据失败断言定位问题；如果没有测试，它会先根据文档和接口行为建立最小验证用例。

剪辑：

- 等待模型响应的空白时间可以剪掉；
- 工具卡片可加速到 1.5 倍，但每个关键工具至少保留 1 秒；
- 不要只保留 Agent 的总结，必须保留实际工具调用画面。

### 0:58-1:18：Agent 修改源代码

画面操作：

1. 保留 `replace_in_file` 或 `apply_diff` 工具卡片。
2. 如果终端展示修改摘要，确保能看到修改目标是 `orders.py`。
3. 不要在此时手动编辑代码，所有修改应由 Agent 完成。
4. 等待 Agent 自动进入下一步，不要输入“继续”，除非 Agent 明确停住。

口播：

> 这里不提前公布具体修复方案。Agent 已经根据项目说明、源代码和测试结果作出判断，现在通过工作区内的修改工具实际更新源文件。对于没有测试的项目，这一步之前还应已经由 Agent 补充最小回归测试。

修改完成并确认测试通过后，退出 Agent 回到项目根目录，再执行：

```powershell
git diff -- demo/tasks/fix_me/orders.py
git status --short -- demo/tasks/fix_me
```

画面中用 Git diff 展示 Agent 实际写入的删除行和新增行。前面已经展示过同一命令无输出，因此这里出现的差异可以直接归因于 Agent 本轮修改。不要在 Agent 修改前展示具体修复代码；只有在 diff 出现之后，才用鼠标或终端高亮解释修改内容。

当前演示中，diff 应能看到与以下逻辑等价的变化：

```diff
-    return f"{amount:.2f}"
+    return f"¥{amount:.2f}"

-    return total - percent
+    return total * (1 - percent / 100)
```

剪辑：

- 保留工具名称、文件路径和成功状态；
- 如果修改参数太长，可以只保留工具卡片的标题和结果摘要，不要遮挡后续测试输出。

### 1:18-1:35：自动测试并完成任务

画面操作：

1. 保留 Agent 调用 `run_tests` 的完整卡片；如果 Agent 之前新建了测试，也要保留新测试文件写入成功的卡片。
2. 重点展示测试命令和执行目录：

   ```text
   python -m unittest discover -s tests -v
   cwd: .
   ```

3. 保留测试成功结果：

   ```text
   Ran 3 tests
   OK
   ```

4. 保留 Agent 的最终总结和本轮步数信息。

口播：

> 修改完成后，Agent 运行受控测试命令验证结果。当前演示中的三个测试全部通过；如果项目原本没有测试，则应展示 Agent 新建的回归测试也通过，再返回最终总结。

剪辑：

- 测试通过画面不要加速，至少保留 3 秒；
- 这是视频最重要的结果画面，不要被字幕或转场遮挡。

### 1:35-1:48：验证工作区状态

画面操作：

1. 在 REPL 中输入：

   ```text
   /status
   ```

2. 展示当前工作区、会话 ID、会话文件和累计步骤。
3. 如画面时间足够，可输入：

   ```text
   /sessions
   ```

   展示会话被保存到当前工作区的 `.coding_agent/sessions/` 目录。

口播：

> 最后查看当前状态，可以看到工作区、会话和累计步骤。每个项目的会话都保存在自己的工作区中，后续可以继续恢复。

### 1:48-1:58：可选的工作区切换镜头

如果希望突出本次新增功能，可以在任务完成后输入一个确实存在的其他目录，例如：

```text
/workspace ..\..\..\test_run\orders
```

然后输入：

```text
/status
```

画面应显示新的工作区和新的会话文件路径。

口播：

> 在多轮对话中，我还可以直接切换到另一个已有项目。切换后 Agent 会重新绑定工具和会话，避免把一个项目的上下文带到另一个项目中。

如果切换镜头导致视频超过 2 分钟，可以删除这一段，保留前面的 `/workspace` 选择镜头即可。

## 五、录制与剪辑检查清单

- 画面只录 PowerShell 或终端，不录 API key、`.env` 和个人隐私路径以外的无关内容。
- 测试现状、任务输入、代码读取、问题定位、代码修改、测试验证和最终工作区状态必须出现；无测试项目还必须出现 Agent 新建回归测试的画面。
- Agent 修改前执行 `git diff -- demo/tasks/fix_me/orders.py` 和 `git status --short -- demo/tasks/fix_me`，两者都应无输出；Agent 完成后再次执行同样的 `git diff`，必须出现源码删除行和新增行。
- 失败测试与成功测试正常播放；模型等待和长 JSON 参数可以剪掉或加速。
- 字幕只标注阶段：`选择工作区`、`发现问题`、`修改代码`、`测试通过`，不要遮挡终端输出。
- 导出为 MP4/H.264，建议 1080p、30fps、6 至 8 Mbps，控制在 200 MB 以内。
- 导出后检查视频时长不超过 2:00，并从头到尾确认画面没有出现 API key 或 `.env` 内容。
