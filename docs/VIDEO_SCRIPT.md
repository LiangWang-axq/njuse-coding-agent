# Coding Agent 2 分钟演示视频大纲与操作稿

## 一、视频目标

在 2 分钟以内演示 Coding Agent 完成一个真实的 Python 编程任务：修复订单金额模块中的两个 bug，并通过自动化测试。同时展示多轮对话模式下的工作区选择能力。

建议成片时长：1 分 50 秒左右；格式：MP4、H.264；文件大小：不超过 200 MB。

本视频必须让观众看到完整闭环：

```text
选择工作区 → 运行失败测试 → 输入自然语言任务 → Agent 读取代码
→ Agent 修改代码 → Agent 运行测试 → 测试全部通过 → 查看工作区状态
```

## 二、录制前准备

以下操作在录制前完成，不必录入视频：

1. 在项目根目录完成一次本地安装：

   ```powershell
   cd D:\NUAA\研\南软\agent
   python -m pip install -e . --no-deps
   ```

2. 确认模型配置可用。API key 只放在 `.env` 或系统环境变量中，不要在视频中打开、复制或展示 `.env`。
3. 确认演示目录处于初始状态：

   ```text
   demo/tasks/fix_me/orders.py       保留两个故意设置的 bug
   demo/tasks/fix_me/tests/test_orders.py  保留 3 个测试
   ```

4. 关闭无关窗口，打开一个较大的 PowerShell 窗口，建议字体 18 至 22 号，保证工具调用和测试结果清晰可见。
5. 录制时从项目根目录开始，不要手动设置 `PYTHONPATH`。

## 三、推荐录制流程

### 0:00-0:07：标题和项目定位

画面操作：

1. 打开 PowerShell，显示项目根目录：

   ```powershell
   cd D:\NUAA\研\南软\agent
   Get-Location
   ```

2. 画面停留 1 秒，让观众看到项目目录。

口播：

> 这是一个不依赖第三方 Agent 框架的 Python 编程智能体。它可以在指定工作区内读取文件、修改代码、运行测试，并通过多轮对话持续完成任务。

剪辑：

- `cd` 和 `Get-Location` 可以正常速度播放；
- 不要展示项目根目录中的 `.env` 内容。

### 0:07-0:20：选择工作区并复现问题

画面操作：

1. 从项目根目录进入演示目录，仅用于执行初始测试：

   ```powershell
   Push-Location .\demo\tasks\fix_me
   python -m unittest discover -s tests -v
   Pop-Location
   ```

2. 保留测试失败输出，重点让观众看到：

   ```text
   Ran 3 tests
   FAILED (failures=2)
   ```

3. 用工作区参数启动 Agent，不需要进入目标目录，也不需要设置环境变量：

   ```powershell
   python -m coding_agent --workspace .\demo\tasks\fix_me
   ```

4. 启动画面出现后，先输入：

   ```text
   /status
   ```

5. 停留在状态输出，确认画面中出现：

   ```text
   工作区: D:\NUAA\研\南软\agent\demo\tasks\fix_me
   ```

口播：

> 我先运行初始测试，可以看到 3 个测试中有 2 个失败。现在通过 `--workspace` 直接选择演示项目作为工作区，Agent 的文件操作和测试都会绑定到这个目录。

剪辑：

- 失败测试不要加速；
- `/status` 的工作区路径至少保留 2 秒；
- 如果路径较长，可以把 PowerShell 窗口横向拉宽，避免换行。

### 0:20-0:30：输入编程任务

画面操作：

在 `你 >` 后输入以下任务，建议提前复制到剪贴板，但录制时只展示粘贴后的完整内容：

```text
检查当前订单计算模块，修复金额格式化与折扣计算的 bug，运行测试直到全部通过，并总结修改内容。
```

按回车后不要继续输入，等待 Agent 开始输出。

口播：

> 这里不直接告诉它修改哪一行，只给出功能目标：检查订单模块、修复两个问题，并运行测试直到全部通过。

### 0:30-0:58：Agent 发现并分析代码

画面操作：

1. 保留 Agent 的第一段说明文字。
2. 保留 `list_files` 工具卡片，展示它确认了当前工作区的文件结构。
3. 保留 `read_file` 工具卡片，展示它读取了：

   ```text
   orders.py
   tests/test_orders.py
   ```

4. 如果出现 `search_code`，保留搜索订单函数或金额计算关键字的那一帧。
5. 如果 Agent 先运行测试，保留 `run_tests` 返回失败的卡片和失败摘要。

预期看到的工具调用顺序大致为：

```text
list_files → read_file → run_tests 或 search_code → 分析问题
```

实际模型可能调整顺序，不需要为了完全一致而重录；只要能看到读取代码、理解测试和定位问题即可。

口播：

> Agent 先查看工作区结构，再读取源代码和测试用例。它通过测试的期望值判断出，第一个问题是金额格式化缺少人民币符号，第二个问题是折扣百分比被错误地直接参与减法。

剪辑：

- 等待模型响应的空白时间可以剪掉；
- 工具卡片可加速到 1.5 倍，但每个关键工具至少保留 1 秒；
- 不要只保留 Agent 的总结，必须保留实际工具调用画面。

### 0:58-1:18：Agent 修改源代码

画面操作：

1. 保留 `replace_in_file` 或 `apply_diff` 工具卡片。
2. 如果终端展示修改摘要，确保能看到修改目标是 `orders.py`。
3. 不要在此时手动编辑代码，所有修改应由 Agent 完成。
4. 等待 Agent 自动进入下一步，不要输入“继续”，除非 Agent 明确停住。

预期修改内容：

```python
return f"¥{amount:.2f}"
return total * (1 - percent / 100)
```

口播：

> Agent 使用工作区内的修改工具更新源文件：金额统一格式化为带人民币符号的两位小数，折扣则先把百分比换算成小数，再计算实际金额。

剪辑：

- 保留工具名称、文件路径和成功状态；
- 如果修改参数太长，可以只保留工具卡片的标题和结果摘要，不要遮挡后续测试输出。

### 1:18-1:35：自动测试并完成任务

画面操作：

1. 保留 Agent 调用 `run_tests` 的完整卡片。
2. 重点展示测试命令和执行目录：

   ```text
   python -m unittest discover -s tests -v
   cwd: .
   ```

3. 保留测试成功结果：

   ```text
   Ran 3 tests
   OK
   ```

4. 保留 Agent 的最终总结和本轮步数信息。

口播：

> 修改完成后，Agent 自动运行受控测试命令。现在 3 个测试全部通过，它根据验证结果返回最终总结，说明任务已经完成。

剪辑：

- 测试通过画面不要加速，至少保留 3 秒；
- 这是视频最重要的结果画面，不要被字幕或转场遮挡。

### 1:35-1:48：验证工作区状态

画面操作：

1. 在 REPL 中输入：

   ```text
   /status
   ```

2. 展示当前工作区、会话 ID、会话文件和累计步骤。
3. 如画面时间足够，可输入：

   ```text
   /sessions
   ```

   展示会话被保存到当前工作区的 `.coding_agent/sessions/` 目录。

口播：

> 最后查看当前状态，可以看到工作区、会话和累计步骤。每个项目的会话都保存在自己的工作区中，后续可以继续恢复。

### 1:48-1:58：可选的工作区切换镜头

如果希望突出本次新增功能，可以在任务完成后输入一个确实存在的其他目录，例如：

```text
/workspace D:\NUAA\研\南软\agent\test_run\orders
```

然后输入：

```text

```

画面应显示新的工作区和新的会话文件路径。

口播：

> 在多轮对话中，我还可以直接切换到另一个已有项目。切换后 Agent 会重新绑定工具和会话，避免把一个项目的上下文带到另一个项目中。

如果切换镜头导致视频超过 2 分钟，可以删除这一段，保留前面的 `--workspace` 启动镜头即可。

## 五、录制与剪辑检查清单

- 画面只录 PowerShell 或终端，不录 API key、`.env` 和个人隐私路径以外的无关内容。
- 失败测试、任务输入、代码修改工具、成功测试和最终工作区状态必须出现。
- 失败测试与成功测试正常播放；模型等待和长 JSON 参数可以剪掉或加速。
- 字幕只标注阶段：`选择工作区`、`发现问题`、`修改代码`、`测试通过`，不要遮挡终端输出。
- 导出为 MP4/H.264，建议 1080p、30fps、6 至 8 Mbps，控制在 200 MB 以内。
- 导出后检查视频时长不超过 2:00，并从头到尾确认画面没有出现 API key 或 `.env` 内容。
